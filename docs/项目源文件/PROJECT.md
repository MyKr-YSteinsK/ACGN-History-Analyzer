# ACGN History Analyzer 项目定义

## 用途

把个人分散的观看、阅读与游玩历史整理成可维护的数据，支持从作品、档期、系列和标签检索记录，以及基于结构化数据做复盘。当前服务于单人、本地使用，主要外部作品来源为 Bangumi。保留 ANIME、COMIC、GAME、NOVEL 四类。

本次接入的验收是恢复原有 Git 基线和工程入口、整理历史原件、完善交接资料并验证兼容整理。升级的产品目标、数据迁移和投入额度由用户根据[审查稿](升级路线与技术审查.md)决定。RunProof 和 config-center 是用户的主力项目。

## 现行数据契约

| 对象 | 当前语义 |
| --- | --- |
| Subject | 作品主数据。发行年和发行档期独立于记录时间。旧代码主要按 Bangumi sourceId 识别来源，实际存量唯一性须以数据库核对为准。 |
| UserSubjectRecord | 一作品一条正式记录，保存个人评分（0–50）、完成年、档期和备注。重复批量导入可覆盖。 |
| UserSubjectCollection | 一作品一条未完成清单记录，状态为 WANT 或 PAUSED。已有正式记录时跳过收藏导入，创建正式记录时移除相应收藏。 |
| 导入匹配 | 记录和收藏依次使用指定的 subjectId、sourceId、标题加可选季／Part。高优先级已给出但找不到时返回缺失，不降级猜测。多候选应在预览阶段明确选择。 |
| 作品重复导入 | 既有条目最多刷新标签、平台评分、集数等现行导入逻辑允许的字段。改写已有标题、档期、系列关系和清理已引用的旧作品属于单独的兼容决策。 |
| Bangumi 往返 JSON | 后端返回 records 文本及可选 subjects 文本。含 Bangumi 来源的正式记录用 sourceId，其余用库内 subjectId。跨库恢复后者需要 ID 映射，收藏、封面和完整主数据另行备份。 |
| 分析 | 结构化上下文是复盘依据。Mock 是本地预览或降级结果，真实模型使用者应明确授权外发范围。 |

保留旧路由、HTTP／JSON 形状、数据语义以及已有主要交互。实际对外契约由代码和可重现的兼容验证提供证据。按任务查阅[架构](../architecture-overview.md)、[数据库](../database-schema.md)、[导入](../import-guide.md)和 [LLM](../llm-guide.md)。

## 角色与交付

- **GPT Project Main** 探索价值、提出路线与验收、审查 Codex 证据和需要用户选择的方案。重要取舍要标清现有证据和受影响的兼容边界。
- **Codex Native** 可在当次授权内直接调查、规划、实施、验证和写回状态。确有多份交接且共享依赖时，可由一个 **Codex Hub** 汇合，按各自验收交付。
- **用户** 决定项目投入、重大改造、数据使用边界、发布和迁移。近期开工内容可细化，远期路线按新证据修订。

普通工作用短任务输入。正式交接以目标仓库 Issue 完整正文优先。写清问题、范围、已批准的硬约束、验收和交付，Issue 链接即可标识任务。创建或更新 Issue 需具备当次授权，公开内容需适合公开。Issue 不可用或含受限信息时，用获授权的可读 Markdown 正文或本地文件。正式 Plan 默认留在交接渠道。

工作区、Git 历史和已有数据按实际状态恢复。操作真实数据库、连接外部模型、Git 推送和发布分别按实际权限执行。报告应区分实际运行证据、静态阅读结果、用户接受和远端交付。只在基线、状态、环境或长期决定发生实质变化时更新对应文件。
